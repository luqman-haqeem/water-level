# workers/

Cloudflare Workers sync pipeline — the replacement for the Convex backend.
Plan and status: [issue #67](https://github.com/luqman-haqeem/water-level/issues/67),
`docs/superpowers/plans/2026-09-02-cloudflare-workers-migration.md`.

**Why:** Convex bills data egress as every byte leaving its cloud, including bytes
out of actions, so mirroring ~11.4 MB of camera frames to R2 every 15 minutes cost
~33 GB/month against a 1 GB free tier. On Cloudflare the same work is free: JPS
ingress is free, Worker to R2 goes over a binding, and R2 to user egress is free.

## Layout

- `wrangler.toml` — `wl-sync`. No cron trigger yet: an empty handler firing every
  5 minutes would publish nothing while looking like it works.
- `src/shared.ts` — the single import point for pure modules still living under
  `convex/`. Phase 7 relocates the sources; only that file changes.
- `src/index.ts` — `wl-sync` entry. Throws until Phase 2.

## Types

`worker-configuration.d.ts` is generated by `wrangler types` from `wrangler.toml` and
committed (same convention as `convex/_generated`). It supersedes
`@cloudflare/workers-types`. **Regenerate after editing `wrangler.toml`:**

```bash
cd workers && npx wrangler types
```

## Tests

Run inside workerd via Miniflare with real (local, simulated) R2 and KV bindings —
no Cloudflare account, no network. Storage is isolated per test file.

```bash
npm run test                  # both projects: app + workers
npx vitest run --project workers
```

## Not verifiable locally

The 10 ms free-plan CPU limit. Miniflare does not enforce it, and neither does a
temporary preview account — 2,048 consecutive full builds in one invocation still
returned 200. Measured at Phase 5 with `wrangler tail` on a real account.
