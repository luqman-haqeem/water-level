# Answer-first home with status strip, pinned sections, and nearest-default sort

This is the v2 review. The v1 review raised four issues — no-data filter bucketing, duplicate cards in the pinned and main grids, stale subscription state, and a location indicator that never disappeared — all of which have been addressed in this revision. The change restructures the station list home screen: a tappable status summary strip replaces the page title, subscribed stations and non-normal stations are pinned above the main grid, the default sort flips from alphabetical to nearest, location is requested unconditionally on mount, and the fake pull-to-refresh is removed.

**Watch for:** "Needs Attention" section bypasses all user-applied filters (district, camera-only, etc.), which may surprise users who have a district filter active (likely). Search text does not narrow the pinned sections, creating a split experience where typing a station name shows it pinned above but removes it from the grid below (confirmed).

**Verdict**: APPROVED

## High-level view

The StatusSummary component counts online non-stale stations into severity buckets and renders tappable colored-dot segments that toggle `alertLevels` in the FilterContext. Counts reflect global state regardless of active district/camera filters — showing "1 alert overall" even if the user has filtered to a single district.

The pinned sections ("My Stations" and "Needs Attention") derive directly from unfiltered `stationsData`, so they always render even when the user has narrowed the main grid via district filters or the search bar. The main grid de-duplicates by excluding pinned IDs. This is correct per the requirements for "My Stations" but less clearly specified for "Needs Attention."

## StatusSummary tap semantics

The tap handler implements toggle behavior: tapping the already-active segment clears the filter (returns to showing all), tapping a different one sets a single-level filter. Multi-select is not supported from the strip — tapping always sets exactly one level or clears. The strip therefore can't replicate the multi-level selection available in the AdvancedFilter dialog, which means a user who activates two levels via the dialog will see neither segment highlighted in the strip (both `isActive` checks fail since `alertLevels.length !== 1`).

## Pinned sections and filter asymmetry

`needsAttentionStations` draws from raw `stationsData` with criteria (online, non-normal alert level, non-stale) and excludes stations already in `myStations`. Neither pinned section passes through `applyAdvancedFilters`. A user filtering to "Johor" still sees alert stations from all districts in "Needs Attention." The spec explicitly requires filter bypass for subscriptions but is silent on "Needs Attention" — this is the core ambiguity in the current implementation.
